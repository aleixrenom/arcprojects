# sheetUtils.ts

## What this file is

The character sheet's non-visual machinery: the ability-pack catalog, game math, localStorage persistence, and the export/import pipeline with its defensive sanitizers. Like [[quizUtils.ts]] for the quiz, it's the "no React here" file — but bigger, because character data is richer and travels further (it can leave as a file and come back).

## Where it fits

- Loads [[abilityPacks.json]] (generated by [[build-ability-packs.mjs]] — the comment warns: never edit the JSON by hand).
- Types from [[character-sheet/types.ts]]; used almost entirely by [[CharacterSheet.tsx]], plus [[AddAbilityModal.tsx]] (the catalog).

## Walkthrough

**The catalog and the refresh rule.** The packs JSON is imported and a `Map` from entry key → entry is built for fast lookup. Then comes one of the file's best ideas:

```ts
function refreshFromCatalog(ability: Ability): Ability {
  const entry = ability.catalogKey ? catalogByKey.get(ability.catalogKey) : undefined;
  if (!entry) return ability;
  return { ...ability, effect: entry.effect, description: entry.description, levels: entry.levels };
}
```

Saved characters carry a *copy* of their abilities' rule text — but the catalog is the source of truth. So on every load (and import), each pack-derived ability gets its text refreshed from today's catalog: rewrite a rule in the design doc, rerun the sync script, and every saved character silently updates. Custom abilities (no `catalogKey`) and abilities whose key vanished from the catalog keep their saved text — nothing is ever lost, just no longer auto-updated.

**Game math.** `tri(n)` is the triangular-number cost — level n costs `n(n+1)/2` points total (1, 3, 6, 10…), making each level pricier than the last; [[CharacterSheet.tsx]] sums it over stats and abilities. `clamp` bounds a number; `uid()` makes ids by gluing random base-36 characters to a timestamp — not cryptographic, but two collisions would need the same random draw *in the same millisecond*.

**Persistence.** `loadSheetState`/`persistSheetState` mirror the quiz's storage code ([[CONCEPTS#localStorage]]): parse inside `try`, validate shape, fall back to a fresh default character on any problem. Two extra touches: old saves predating the Expertise card get `expertise` backfilled as an empty array (so no other code needs to ask "is it there?"), and every loaded ability passes through `refreshFromCatalog`. Even *saving* is wrapped in `try` — in private browsing modes storage can refuse writes, and the sheet then simply lives in memory rather than crashing.

**Export.** `downloadCharactersFile` shows how a web page "saves a file" without any server:

```ts
const blob = new Blob([JSON.stringify(payload, null, 2)], { type: "application/json" });
const url = URL.createObjectURL(blob);
const link = document.createElement("a");
link.download = `${slug}-${date}.json`;
link.click();
```

Build the JSON in memory (a `Blob` is a file-like chunk of data), mint a temporary URL for it, create an invisible download link, click it programmatically, then revoke the URL. The payload is a versioned envelope — `{ app, version, characters }` — so the import side can recognize its own files, and one shape covers single- and all-character exports. The filename is slugged from the character name plus today's date.

**Import — trust nothing.** An imported file is arbitrary text from outside the app, so it goes through three layers: `parseImportedCharacters` checks the envelope (`app` marker, non-empty `characters` array) and *throws* on anything else — the caller ([[CharacterSheet.tsx]]) turns that into the friendly error message; `sanitizeCharacter` rebuilds each character starting from `defaultCharacter()`, accepting only fields of the right type and clamping every number; `sanitizeAbility` does the same per ability (dropping any without at least a name) and ends with `refreshFromCatalog`. Note every import gets a **fresh id** — the file's ids could collide with characters already on the sheet, e.g. when re-importing your own export. The `(a): a is Ability` filters are TypeScript *type-guard* syntax ([[CONCEPTS#TypeScript]]): "after this filter, trust these are real Abilities".
